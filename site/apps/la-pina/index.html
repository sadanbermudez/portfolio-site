    The method

    methodology v2

    Every verdict is a list of rules

    The method combines a trend template, the classic base patterns (cup with handle, Darvas box, flags) and a breakout volume rule the app calls PAVA. Structural filters reject; temporary blocks only hold an asset on watch; a 0 to 100 score decides the rest. Only closed daily bars count, never intraday prices.

    The rules of the method, in evaluation order

    How it's built

    Kotlin · four modules

    A pure engine, a data layer, and an Android shell

    engine

    pure Kotlin/JVM · 263 tests

    Indicators, the trend template, RS, the bases, PAVA, overhead supply, the regime state machine, score, verdict, stops, sizing, the paper portfolio's sell rules, the backtest, the heat map layout. No Android imports, so it runs and is tested on the JVM.

    marketdata

    pure Kotlin/JVM · 67 tests

    Data sources behind one interface, the symbol catalog, the nightly scan service, the cache refresh, SEC EDGAR's filings and the macro panel's sources.

    learn

    pure Kotlin/JVM

    The course: 85 lessons in Markdown, links from lessons into the app, progress, tests and card review.

    app

    Android · Compose

    Jetpack Compose with Material 3 and fixed brand colours, Room (schema v7) for the cache, lists, alerts and the paper portfolio, WorkManager for the nightly scan, manual dependency injection instead of Hilt, and Lightweight Charts in a WebView.

    Data, all free

    Daily bars from Yahoo's chart endpoint by default; US companies' filings and earnings dates from SEC EDGAR; macro figures from the ECB, the BLS, the US Treasury and the New York Fed. No keys and no subscriptions. Only closed daily bars enter a verdict.

    What this web demo ports

    engine.js reproduces the Analyzer (H1-H6, B1-B5, score, plan), the four bases, PAVA with its weekly variant, overhead supply, the RS line, the regime state machine, the "what is missing" texts, the automatic lists, sizing and the squarified treemap. The tests in site/tests/la-pina.test.mjs run the Kotlin fixtures and expect the same verdicts. The random walks use a bit-for-bit port of java.util.Random, the generator the app's screenshot tool seeds.

    Left out: gold, silver and bitcoin's adapted rules, the chart-pattern detector (flat bases from ranges and the B7 bearish-pattern block), the fundamentals layer, trading costs and the full backtest. Those are in the app, not here.

    Honest notes

    • It is an education tool. It never places orders and connects to no broker; the user decides and carries the risk.
    • The app's backtest is conservative about what it can claim: until there is an out-of-sample test, every setup is labelled "Muestra insuficiente" against its index, with the SPIVA base rate next to it.
    • The method's defaults come from its written specification, and the code says so itself: they are settings, not facts.
    • Everything on this page is simulated. No real company, price or trade appears.
