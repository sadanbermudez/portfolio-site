Signature piece

photonics-lab-mcp

An AI agent runs a physics experiment, inside limits it cannot override

An MCP server gives a local 35B model an optics bench. One question, no procedure: is the 1270 nm emission excited by one photon or two? The answer is hidden in the server. Below is the agent's real run, call by call.

agent · Qwen3.6-35B · local
#25acquire_spectrum({"label":"P160mW"})max 6,636
#26fit_power_dependence({"run_ids":[6 runs],"center_nm":1270})n = 2.004 ± 0.03
#27laser_emission({"on":false})
#28safe_state({"reason":"measurement complete"})safe
→conclusion: two-photon, exponent 2.004 ± 0.03correct
peak area vs power · log-logslope = photon order

Right twice. The control run uses a one-photon sample under the same 800 nm question, and the agent measured 1.003. It read the slope instead of reciting the textbook answer.

Wrong twice, too. Both closing explanations got the photophysics wrong: the sensitiser absorbs, and its triplet state passes the energy to oxygen. So the server owns safety and statistics, and a person owns interpretation.

Case study

llama.cpp · Vulkan

A 20x stall, found one measurement at a time

Every reply from my local assistant stalled for over a second. The cause: the CPU was reading model snapshots straight out of GPU memory it cannot cache. The animation runs at the measured speeds.

Reading 880 MB of model state on an integrated GPUdots move at measured throughput (14 : 1)

Same output word for word at temperature 0, before and after. The same fix had been merged upstream two weeks earlier (llama.cpp #30049), so this is an independent diagnosis, not a contribution.
