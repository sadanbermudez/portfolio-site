An AI agent that runs a physics experiment

An MCP server gives a local language model an optics bench, with safety limits it cannot override. I asked it one question with a hidden answer and no procedure.

Two-photon samplen = 2.004 ± 0.03
One-photon controln = 1.003 ± 0.002
Tool calls per run28 and 32

The question

"The bench excites a photosensitiser with an 800 nm laser and records emission near 1270 nm. Determine experimentally whether this emission is excited by one-photon or two-photon absorption, and state your conclusion with its uncertainty."

Signal grows as Pn, where n is the number of photons absorbed per excitation, so the slope on a log-log plot gives the answer. The agent had to work that out, choose powers and integration times that keep the detector out of saturation, take the spectra, fit the peaks, fit the power law and conclude. The photon order is a hidden server setting, so the same question has a different right answer in each run.

The bench is a physics simulator: Poisson shot noise, read noise, dark current and saturation on a 512-pixel InGaAs spectrometer. The tool surface, safety layer, analysis and notebook are the code a real bench would use. A Thorlabs PM100 power-meter driver (SCPI over VISA) is included and tested against a simulated instrument; it has not yet run on hardware.

Reading it

A reliable operator, a careless interpreter

The control matters. At 800 nm the textbook guess is "two-photon". The control run uses the same setup with a one-photon sample, and the agent still measured 1. It read the slope instead of reciting the expected answer.

What it got wrong. The measurements and fits were sound; the closing physics was not, in both runs. In the first it tied the 3.1 eV of two 800 nm photons to the singlet-oxygen emission, which is 0.98 eV. In the second it described singlet oxygen as excited by absorption from the triplet state. In fact the sensitiser absorbs the light, and its triplet state passes the energy to oxygen; the photon order describes the sensitiser.

That split is the case for the design: the server owns the safety limits and the statistics, and a person checks the interpretation.

Design

10 tools · 22 tests

Safety lives in the server

  • A power cap (200 mW by default), an arm-then-emit interlock, and read-only, configure and full permission levels, so a read-only client cannot touch the laser.
  • Any unexpected error puts the bench in its safe state before the tool returns.
  • Every action, including every refused one, goes into a lab notebook the agent can read back.
  • Peak fits report the area with its uncertainty and flag saturation; the power-law fit weights each point by its error and scales the slope's uncertainty by the reduced chi-squared.
  • The PM100 driver refuses out-of-range wavelengths before sending a command, and is tested against a simulated SCPI instrument.
