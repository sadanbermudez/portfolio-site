Argus: a local agent system, and a llama.cpp latency fix

  • Runs my assistant on a local 35B mixture-of-experts model (Qwen3.6-35B-A3B, llama.cpp on Vulkan, AMD integrated GPU) inside the open-source Odysseus hub, with an MCP memory server I wrote (seven tools, path confinement, no deletes), a bridge that hands hard jobs to Claude Code, voice, and a supervisor that restarts failed services.
  • Chose every setting by evaluation: 13 real tasks with deterministic checks; thinking off scored 13/13 at a 2.6 s median against 10/13 at 19.8 s with thinking on.
  • Traced a 3-second pause before every spoken answer to the Vulkan backend reading uncached GPU memory (880 MB in 7.7 s). One condition cut a state snapshot from 0.61 s to 0.03 s and the first spoken word to about 0.7 s, with identical output. The maintainer had merged the same fix two weeks earlier, so it is an independent diagnosis, not a contribution.

moe-offload-lab: why a 284B model runs at 0.5 tokens per second

  • Modelled bytes per token, benchmarked the SSD (4.8 GB/s, while the engine read 0.72), wrote an AVX-512 FP4 kernel in C++20, profiled the engine and disassembled the shipped binary (no AVX-512 instructions).
  • Rebuilt the engine with clang and changed one variable at a time: AVX-512 alone was worth about 9%, while a larger gain of about 55% came from how threads wait at roughly 500 barriers per token on Windows. Reported upstream.
